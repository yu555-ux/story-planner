# 剧情规划器（SillyTavern 原生扩展）

当前版本：**0.1.3**。仓库默认分支 `main` 的根目录包含可安装扩展的 `manifest.json`、入口、样式和运行模块。扩展使用 SillyTavern 原生 API，不依赖 Tavern Helper / JS-Slash-Runner。

## 安装

在 SillyTavern 的“扩展 → 安装扩展”中填写：

- Git URL：`https://github.com/yu555-ux/story-planner`
- Branch or tag name：**留空**，安装默认分支 `main`。

已从本仓库 `main` 安装的用户可在扩展管理器中更新并刷新页面。若现有安装指向其他仓库或分支，Git 更新不会自动切换来源；请先导出规划预设、备份 API 配置，再使用上述地址重新安装。已保存的 API 密钥以圆点遮罩提示；密钥值不会回填，留空保存会保留原密钥。

安装后启用“剧情规划器”并刷新页面。点击聊天输入框旁的魔法棒，在菜单中选择“剧情规划器”，进入“设置”页填写独立规划 API 的 OpenAI 兼容基址、密钥和模型，并导入规划预设。点击面板顶部的开关按钮即可立即启用；按钮和结果页状态区会显示开关状态。

## 首次规划

新聊天只有角色开场白（0 楼）时，发送第一条玩家消息（1 楼）。扩展会在酒馆首次回复（2 楼）生成前调用规划器生成细纲；规划成功后才放行酒馆回复，并把 `<outline>…</outline>` 追加到本次 Chat Completion 提示词末尾。

## 当前范围

- 只规划细纲；大纲、节点、精确提示词插入位置和 Text Completion 拦截尚未实现。
- “规划结果”页按顺序保存本聊天的细纲历史，显示来源楼层、实际使用楼层和待使用/已使用/失效/替换状态；正文只显示 `<outline>` 内部内容。失败任务单独显示状态，不覆盖成功历史。
- 规划请求使用 SillyTavern 的 Chat Completion 同源后端。API 基址可包含 `/chat/completions` 后缀，扩展会自动处理。
- 规划请求只从响应副本读取原始 JSON，保留 `game_content` 工具调用，不触发酒馆主预设包装的 `response.json()` 输出转换。这覆盖正式规划、连接测试和工具探针；不会修改全局 `fetch` 或酒馆预设。仍共用酒馆后端，不保证隔离其他扩展对请求或整个响应体的改写。
- “测试连接”只验证非空普通回复；“测试工具调用”会用最短提示和当前预设中的 `game_content` 定义，依次比较指定工具、必须调用和自动选择三种格式，最多调用 API 三次且不写入聊天。结果用于区分 `tool_choice` 格式、完整规划提示词和独立请求路径问题。
- 排查工具调用时，在浏览器开发者工具的 Console 中筛选 `[剧情规划器][诊断]`。`[提示词组装]` 记录规划器最终生成的消息数量、角色、文本长度和指纹；`[请求]` 对比传入酒馆 Chat Completion 载荷前后的消息摘要；`[发送前]` 记录即将交给 `fetch` 的序列化请求体中的消息摘要。三处摘要指纹相同且 `matches` 为 `true`，表示目前没有发现扩展组装到请求体之间的消息差异；这不能单独证明服务端或模型实际收到的内容，可在开发者工具 Network 面板查看请求体确认。
- `[响应]` 的 `responseSource: "cloned_http_body"` 表示规划器使用原始响应副本；`wrappedJsonInvoked: false` 表示没有触发原对象的输出转换。`raw` 记录工具调用数量和名称、结束原因、正文字符数及 `<outline>` 标签状态；工具细纲位于工具参数中，因此原始普通正文没有 `<outline>` 标签并不代表细纲缺失。日志不包含 API 密钥、提示词正文、回复正文或工具参数；`fnv1a-*` 指纹只用于本地比对，不是加密校验。
- 行为测试覆盖首次拦截、后续轮次规划、聊天状态存储、API 请求适配和提示词注入。

## 0.0.9：本轮、下一轮与重试

- 首次发送前生成本轮细纲；酒馆回复结束后，后台生成下一轮细纲。
- 后台任务以当时的聊天前缀为依据。玩家随后输入消息时，继续等待同一个任务，不追加第二次请求；发送前若后台已经失败或缺少有效细纲，则执行本轮补救，成功后放行。
- 设置新增“失败重试次数”，默认 2，范围 0–10；2 表示首次请求加最多两次重试。沿用“请求超时（秒）”作为每个规划任务的总时限，含准备提示词、API 调用、重试和重试间隔。补救是新的任务，获得新的总时限。
- 网络失败、HTTP 408/429/5xx、空回复、缺少或重复/不完整 outline 标签、无效工具参数等可以重试；401/403/404、配置和预设错误直接失败。总超时到达后结束任务。
- 重试沿用冻结的提示词。通知只在最终失败时出现一次，并区分“本轮失败，阻止回复”和“下一轮失败，下次发送前补救”。控制台的 [任务]、[重试] 日志显示时期、来源楼层及尝试次数，不输出提示词和密钥。
- 细纲先记录来源楼层；提示词注入后，收到最终助手消息才绑定实际使用楼层，不固定假设增加两层。新增成功记录不会覆盖旧记录；手动重规划保留旧版本，并标记被替换的待使用记录。
- 聊天标识、前缀内容指纹、规划配置及预设共同匹配待使用细纲。编辑/删除/切换回复后重新验证，迟到的过期响应不能发布。关闭规划器或切换聊天会取消任务；重新打开聊天保留历史。旧版本细纲保留浏览，但因缺少完整进度凭据，不直接注入。
- 历史保存在当前聊天元数据，导出聊天时会一起保存；规划结果正文按纯文本显示。

时序参考：SillyTavern 1.18.0 固定提交 [8172dcd 的 public/script.js](https://github.com/SillyTavern/SillyTavern/blob/8172dcd0ee672d3cd9a5e5f7af134f91a45cd2b8/public/script.js)。MESSAGE_RECEIVED 可在工具调用中间消息完成时触发，生成结束事件与消息事件的顺序在流式和非流式路径不同，因此扩展同时跟踪 GENERATION_STARTED / GENERATION_ENDED，并合并重复消息事件。该源码检查与离线测试不能替代用户当前实例的实际验收。
