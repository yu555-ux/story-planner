# 剧情规划器（SillyTavern 原生扩展）

当前版本：**0.2.2**。仓库默认分支 `main` 的根目录包含可安装扩展的 `manifest.json`、入口、样式和运行模块。扩展使用 SillyTavern 原生 API，不依赖 Tavern Helper / JS-Slash-Runner。

## 安装

在 SillyTavern 的“扩展 → 安装扩展”中填写：

- Git URL：`https://github.com/yu555-ux/story-planner`
- Branch or tag name：**留空**，安装默认分支 `main`。

已从本仓库 `main` 安装的用户可在扩展管理器中更新并刷新页面。若现有安装指向其他仓库或分支，Git 更新不会自动切换来源；请先导出规划预设、备份 API 配置，再使用上述地址重新安装。已保存的 API 密钥会在密码框中以圆点遮罩显示，可直接替换；清空后保存会移除密钥。

## 版本发布约定

后续版本只发布到仓库默认分支 `main`。更新版本号、提交并推送到 `main` 后，以 GitHub 上 `main` 的 `manifest.json` 版本和文件内容为准确认发布完成。开发分支可用于准备改动，但不作为酒馆安装或更新来源；用户安装时 Branch or tag name 始终留空。

安装后启用“剧情规划器”并刷新页面。点击聊天输入框旁的魔法棒，在菜单中选择“剧情规划器”，进入“设置”页填写独立规划 API 的 OpenAI 兼容基址、密钥和模型，并导入规划预设。点击面板顶部的开关按钮即可立即启用；按钮和结果页状态区会显示开关状态。

## 首次规划

新聊天只有角色开场白（0 楼）时，发送第一条玩家消息（1 楼）。扩展会在酒馆首次回复（2 楼）生成前调用规划器生成细纲；规划成功后才放行酒馆回复，并把 `<outline>…</outline>` 追加到本次 Chat Completion 提示词末尾。

## 当前范围

- 只规划细纲；大纲、节点、精确提示词插入位置和 Text Completion 拦截尚未实现。
- “规划结果”页显示仍有效的待使用、本轮使用中和已使用细纲；失去依据或被新版本取代的记录只写入不含正文的诊断日志，不显示为历史分类。正文只显示 `<outline>` 内部内容。失败任务单独显示状态，不覆盖成功历史。
- 规划请求使用 SillyTavern 的 Chat Completion 同源后端。API 基址可包含 `/chat/completions` 后缀，扩展会自动处理。
- “单次规划请求超时（秒）”分别限制首次尝试和每次重试，覆盖该次提示词准备、API 调用与响应解析；重试等待不计入，每次重试会重新获得完整时限。
- 规划请求只从响应副本读取原始 JSON，保留 `game_content` 工具调用，不触发酒馆主预设包装的 `response.json()` 输出转换。这覆盖正式规划、连接测试和工具探针；不会修改全局 `fetch` 或酒馆预设。仍共用酒馆后端，不保证隔离其他扩展对请求或整个响应体的改写。
- “测试连接”只验证非空普通回复；“测试工具调用”会用最短提示和当前预设中的 `game_content` 定义，依次比较指定工具、必须调用和自动选择三种格式，最多调用 API 三次且不写入聊天。结果用于区分 `tool_choice` 格式、完整规划提示词和独立请求路径问题。
- 排查工具调用时，在浏览器开发者工具的 Console 中筛选 `[剧情规划器][诊断]`。`[提示词组装]` 记录规划器最终生成的消息数量、角色、文本长度和指纹；`[请求]` 对比传入酒馆 Chat Completion 载荷前后的消息摘要；`[发送前]` 记录即将交给 `fetch` 的序列化请求体中的消息摘要。三处摘要指纹相同且 `matches` 为 `true`，表示目前没有发现扩展组装到请求体之间的消息差异；这不能单独证明服务端或模型实际收到的内容，可在开发者工具 Network 面板查看请求体确认。
- `[响应]` 的 `responseSource: "cloned_http_body"` 表示规划器使用原始响应副本；`wrappedJsonInvoked: false` 表示没有触发原对象的输出转换。`raw` 记录工具调用数量和名称、结束原因、正文字符数及 `<outline>` 标签状态；工具细纲位于工具参数中，因此原始普通正文没有 `<outline>` 标签并不代表细纲缺失。日志不包含 API 密钥、提示词正文、回复正文或工具参数；`fnv1a-*` 指纹只用于本地比对，不是加密校验。
- 行为测试覆盖首次拦截、后续轮次规划、聊天状态存储、API 请求适配和提示词注入。

## 细纲与楼层的对应

- 对同一条玩家输入反复重生成或切换回复 swipe，会继续使用同一份本轮细纲；旧回复派生的下一轮细纲会在回复变更后清理，等新回复确定后再生成。
- 删除本轮 AI 回复后，如果生成依据和玩家输入仍存在，本轮细纲回到待使用；删除其来源楼层则清理依赖它的细纲。酒馆一次删除多楼时按删除前后的完整消息快照统一对账。
- 删除玩家输入时暂存细纲的输入指纹，直到出现下一条玩家输入；提示词相关正文和附件相同才复用，不同则重新规划。无法唯一确认消息归属时会清理并在下次发送前补救。
- 前台规划在宿主原生异步生成拦截器中等待，按钮状态沿用宿主生成流程；回复结束后的下一轮细纲和手动细纲生成期间，规划器会占用酒馆原生发送区域并阻止提前发送。原生停止键可取消当前规划任务；取消下一轮任务后，下次发送前仍会补救细纲。成功、失败、超时或切换聊天后会释放规划器占用。按钮外观与移动端输入法行为仍需在目标宿主版本实机验收。

## 0.2.2：每次规划尝试独立计时

- 单次规划请求超时分别作用于首次请求和每次重试；超时会取消当前尝试并按配置重试，重试等待不计入时限。
- 设置页明确标注单次请求时限；README 同步说明提示词准备、API 调用和响应解析均属于单次尝试。

## 0.2.1：规划期间占用酒馆发送键

- 后台生成下一轮细纲或手动规划时，原生发送区域显示忙碌状态，并阻止点击发送、回车及 Ctrl+Enter 提前启动下一轮。
- 点击原生停止键可取消当前规划请求；取消下一轮规划后，再次发送会先补救细纲。
- 规划结束、失败、超时及切换聊天时释放发送区域；接续酒馆 AI 回复时由酒馆继续保持自身的生成状态。

## 0.2.0：细纲与楼层生命周期优化

- 同一玩家输入下重生成或切换回复 swipe 时复用同一份本轮细纲；被替换回复派生的下一轮细纲会清理，并在新回复确定后重新预生成。
- 删除本轮 AI 回复后，仍有生成依据和玩家输入的细纲回到待使用；批量删楼按删除前后快照统一对账。删除玩家输入后只保留隐藏的匹配候选，同内容与附件才复用。
- 结果页只显示待使用、本轮使用中和已使用细纲。失去依据或被替换的记录仅留不含正文的诊断日志。
- 前台规划沿用宿主的异步生成拦截流程；后台预生成不占用发送键。停止、失败、超时和聊天切换会结束前台等待。

## 0.0.9：本轮、下一轮与重试

- 首次发送前生成本轮细纲；酒馆回复结束后，后台生成下一轮细纲。
- 后台任务以当时的聊天前缀为依据。玩家随后输入消息时，继续等待同一个任务，不追加第二次请求；发送前若后台已经失败或缺少有效细纲，则执行本轮补救，成功后放行。
- 设置新增“失败重试次数”，默认 2，范围 0–10；2 表示首次请求加最多两次重试。当时“请求超时（秒）”按每个规划任务共用总时限，含准备提示词、API 调用、重试和重试间隔；当前版本已调整为每次尝试单独计时。
- 网络失败、已确认的上游 HTTP 408/429/5xx、酒馆宿主 502/503/504（没有明确的认证或请求参数错误）、后端连接断开、空回复、缺少或重复/不完整 outline 标签、无效工具参数等可以重试；401/403/404、明确的权限或配置错误直接失败。若接口以 `finish_reason: length` 标记输出未完成，会提示调大最大输出长度，不把该结果当作细纲。
- 重试沿用冻结的提示词。通知只在最终失败时出现一次，并区分“本轮失败，阻止回复”和“下一轮失败，下次发送前补救”。控制台的 [任务]、[重试] 日志显示时期、来源楼层及尝试次数，不输出提示词和密钥。
- 细纲先记录来源楼层；提示词注入后，收到最终助手消息才绑定实际使用楼层，不固定假设增加两层。手动重规划成功后，新的待用细纲取代同一目标的旧待用版本。
- 聊天标识、前缀内容指纹、规划配置及预设共同匹配待使用细纲。编辑/删除/切换回复后重新验证，迟到的过期响应不能发布。关闭规划器或切换聊天会取消任务；重新打开聊天保留仍可验证的记录。不可验证的旧记录在迁移时清理。
- 历史保存在当前聊天元数据，导出聊天时会一起保存；规划结果正文按纯文本显示。
