# 变量剧情器

SillyTavern 原生扩展。它为每个聊天保存总纲、卷纲、事件纲和细纲，在正文生成前补齐缺少的提纲，并根据最终选用的助手回复推进阶段。

## 安装与使用

将扩展目录安装到 SillyTavern 的第三方扩展目录，启用后刷新页面。从输入框旁的魔法棒打开“变量剧情器”。在“设置”页填写独立规划 API 的 OpenAI 兼容地址、密钥和模型；扩展内置一份默认规划预设，供上三纲和细纲共用。打开扩展开关后，首次正常生成正文时会自动规划。单纯打开聊天或查看第 0 楼不会调用规划 API。

“剧情进度”页依次显示四层当前提纲、活动阶段、待重写请求和下一次生成前需要补齐的层级。手动补录入口位于页面底部的折叠区，可粘贴与当前缺口相符的完整标签块。卷纲、事件纲和细纲均可一次提供多份同层提纲，作为同一父阶段的批次。

## 四层提纲

| 层级 | 标签 | 阶段来源 |
| --- | --- | --- |
| 总纲 | `<overall_outline>` | 无阶段，提供长期方向 |
| 卷纲 | `<volume_outline>` | “关键事件”列表，每项一个阶段 |
| 事件纲 | `<event_outline>` | `阶段x:` 小节 |
| 细纲 | `<fine_outline>` | `阶段x:` 小节；没有阶段标题时按一个阶段处理 |

“设置”页的“多次调用”开关默认关闭。关闭时，每个请求一次生成当前缺少的所有层级；开局请求生成总纲、卷纲、事件纲和细纲。开启时，上三纲和细纲分开请求；上三纲请求不发送标题含“细纲”的词块，细纲请求不发送标题含“总纲”“卷纲”或“事件纲”的词块。正文末尾的 `<planner_update>` 使用 `set(卷纲.阶段完成, true)`、`set(事件纲.阶段完成, true)`、`set(细纲.阶段完成, true)` 回报已经发生的完成情况。各层独立推进；上层阶段要求完成时，仍要等其下层阶段走完。重写请求在回复结算后保存，于下一次正文生成前执行。

具体字段、批次父阶段关系和回报语法见 [变量剧情器最新方案](docs/plans/2026-10-09-变量剧情器最新方案.md)。

## 规划预设

规划 API 只发送默认预设组装出的消息。扩展不会在消息末尾追加隐藏的规划任务提示词；默认预设的“总结”词块使用 `{{planner_kind}}`、`{{planner_scope}}` 和 `{{planner_context}}` 告诉模型当前任务、允许输出的标签和已有规划。可在预设页编辑词块、检查设置并预览实际发送的消息。

上三纲和细纲共用这一份预设及同一套 API 连接设置。API 密钥保存在扩展设置中；聊天提纲保存在该聊天的扩展元数据中。切换聊天、停止生成、修改配置或预设时，未完成的规划请求会失效。规划失败会阻止本次正文生成，已保存的提纲保持可用，下次发送可重试。

## 开发验证

在本目录运行 `node --test *.test.mjs`。测试覆盖四层解析与阶段结算、预设消息组装、正文注入、宿主请求与聊天存储。实际 SillyTavern 页面中的交互仍需在目标宿主版本验收。
